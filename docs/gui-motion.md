# Iced 动效与界面精修

## 结论

当前 Iced 0.14 可以实现适合启动器的短动效，tiny-skia 不妨碍插值、位移、缩放和控件状态反馈。
基础微动效不需要切换 GPU 后端或额外动画库。它不是 CSS transition：状态、时间和绘制请求需要显式连接，
复杂页面编排、自定义转场和跨元素动画的工程量明显更高。

轻量启动器适合 100–220ms 的操作反馈与面板展开，不适合依靠持续动画来营造视觉效果。
软件渲染下的实际流畅度取决于窗口尺寸、文字/图形复杂度和设备；未做原生性能实测，不能承诺固定帧率。

## 已核实的能力与来源

- [Iced 0.14 `Animation`](https://docs.rs/iced/0.14.0/struct.Animation.html)：内置状态插值、缓动、时长、延迟及进行中判断；
  本地 `iced_core 0.14.0/src/animation.rs` 与公开 API 一致，内部基于 lilt。
- [Iced `Shell`](https://docs.rs/iced/0.14.0/advanced/struct.Shell.html)：控件可以请求下一次绘制，
  不必同时发送应用消息或使整个页面布局失效；可以让动画停止后回到事件驱动。
- [iced_anim 0.3.1](https://docs.rs/iced_anim/0.3.1/iced_anim/)：提供额外动画封装和弹簧模型，
  发布依赖兼容 iced_core 0.14 / iced_widget 0.14.2；本项目这些短动效没有引入它的必要。
- 增加组件库前仍需审查 Cargo features，不能因应用直接依赖关闭默认 features 就假定传递依赖不会再启用 wgpu。
  当前实现没有新增依赖或 renderer features。

## 本项目的取舍

- 保持白色/zinc、系统中文字体、72px 导航和真实业务布局，不另做一套主题或装饰性背景。
- 让游戏摘要比配置/更新操作安静：摘要用轻底色和较少边框，主操作保持清楚。
- 日志属于跨页诊断，放全局底栏/抽屉；操作结果独立于日志流，不让它被下一条日志顶掉。
- 抽屉固定高度，只在绘制阶段位移并裁剪；主页面不随动画改变高度，避免反复重排。
- 固定裁剪边界需逆变换到子控件坐标，随视口传递给嵌套控件；Iced 新建的裁剪层不自动与父层相交，
  只建外层 clip 会让抽屉内文字、选区和按钮随位移越过底栏。
- 按钮只做轻微按下反馈，不用弹跳、循环、持续脉冲、大面积模糊或卡片悬浮放大。
- 主/次/弱/危险按钮、分段和导航保留明确的 hover/pressed 样式；这种颜色/边框反馈无需依赖动效，禁用状态不高亮。
- 动画 200ms/100ms，统一 ease-out，支持中途反转；在 widget 内只请求短暂重绘。
- `EORZEA_REDUCED_MOTION=1` 禁用这些过渡。通知消失使用一次性延迟任务，不使用常驻刷新计时器。
- 只读日志选择区不启用 IME，也不为光标闪烁持续刷新；新日志不冲掉正在阅读的文本快照和选区。

无窗口测试检查状态、事件、像素布局、过渡无布局失效及结束后无继续重绘请求；复用控件树和每段过渡的布局，
在普通/150% 缩放下逐帧检查收起、完全关闭、重开、中途反转的底栏像素隔离和结束帧一致性。
真实窗口、中文 IME、平台输入、动效帧率及 CPU/RAM 仍须在获准或真正隔离的环境验证。
